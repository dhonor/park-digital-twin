## 1. 运行形态与端口

项目只有两种进程：**一个 FastAPI 服务** + **一份前端静态产物**。没有消息队列、没有独立前端容器、没有反向依赖。

| 形态 | 命令 | 端口 | 前端来源 | 用途 |
| --- | --- | --- | --- | --- |
| A 单端口 | `uvicorn app.main:app` | 8000 | 后端托管 `frontend/dist` | 首跑、演示、生产 |
| B 开发热更新 | `uvicorn --reload` + `vite` | 8000 / 5173 | Vite dev server | 改代码 |
| C 前端独立托管 | `uvicorn` + Nginx | 8000 / 80 | Nginx 托管 `dist` | 生产（推荐） |

| 端口 | 归属 | 说明 |
| --- | --- | --- |
| 8000 | Uvicorn | `/api`、`/api/ws/realtime`、`/docs`，形态 A 下还包括前端 |
| 5173 | Vite | 仅开发；`/api`（含 WebSocket）代理到 8000 |
| 4173 | `vite preview` | 仅本地验证构建产物 |
| 5432 | PostGIS 容器 | 可选 |
| 8080 | GeoServer 容器 | 可选，`ogc` profile |

前后端只有一个耦合点：**HTTP 相对路径 `/api`**。前端代码里没有任何硬编码域名，因此换部署拓扑不需要改代码。

## 3. 配置项总表

配置来源有三处，优先级从高到低：**进程环境变量 → `backend/.env` → 代码默认值**。

`backend/app/config.py` 里的 `_load_dotenv()` 用 `os.environ.setdefault()` 写入，所以系统/容器注入的环境变量**不会被 `.env` 覆盖**——生产环境用容器或 systemd 注入即可，不需要写文件。

### 后端（`backend/app/config.py`）

| 变量 | 默认值 | 生产建议 | 作用 |
| --- | --- | --- | --- |
| `DATABASE_URL` | 空 | 空（演示）或 `postgresql://…` | 空 = 内存仓库读 `data/*.geojson`；非空 = PostGIS 仓库，启动时自动切换 |
| `PARK_DATA_DIR` | `<项目>/data` | 与代码分离时显式指定 | 原始要素目录（唯一真源） |
| `FRONTEND_DIST` | `<项目>/frontend/dist` | 显式绝对路径 | **启动时若目录不存在则跳过静态托管**，见 §8.1 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 同源部署可留空；跨域部署填前端域名 | 逗号分隔，空值退化为 `*` |
| `TELEMETRY_INTERVAL` | `2.0` | 按设备量上调 | 遥测模拟推送周期（秒），同时下发给前端 |
| `CACHE_TTL_SECONDS` | `30` | 30–60 | 图层/概览响应缓存 TTL（进程内或 Redis） |
| `REDIS_URL` | 空 | 多副本时必填，如 `redis://redis:6379/0` | 空 = 单进程（缓存/广播/设备状态都在进程内）；非空 = 缓存与事件走 Redis，可水平扩副本 |
| `DEFAULT_LOD` | `1` | `1` | `/api/layers` 返回的默认精度，前端首帧使用 |
| `GEOSERVER_URL` | 空 | 空即可 | 仅用于 `/api/park` 里标记 `ogc_services: true` |

> 配置是**模块级冻结 dataclass**，进程启动时读取一次，改 `.env` 必须重启进程（`--reload` 只监听代码）。

### 前端（构建期注入）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE` | `/api` | 仅当 API 与页面不同源时设置，**在 `npm run build` 时被内联进产物**，改它必须重新构建 |

前端还依赖一个隐式约定：Cesium 静态资源位于 `public/cesium/`，由 `frontend/scripts/copy-cesium.mjs` 在 `npm install` / `dev` / `build` 前自动拷贝（幂等，带版本戳 `.cesium-version`）。该目录已被 `.gitignore` 忽略，**不能只拷 `dist/` 而不拷 `dist/cesium/`**。

### 三套环境的推荐取值

| 变量 | 开发 | 测试 | 生产 |
| --- | --- | --- | --- |
| `DATABASE_URL` | 空（内存） | `postgresql://park:park@<test-host>:5432/park_twin` | `postgresql://<user>:<pwd>@<db-host>:5432/park_twin` |
| `CORS_ORIGINS` | `http://localhost:5173` | `http://<test-host>` | 同源留空，或 `https://<domain>` |
| `TELEMETRY_INTERVAL` | `2.0` | `2.0` | `2.0`（接 MQTT 后此值失效） |
| `CACHE_TTL_SECONDS` | `5`（改数据立即生效） | `30` | `30` |
| `DEFAULT_LOD` | `1` | `1` | `0`（大屏）或 `1` |
| 前端 | `npm run dev` | `npm run build` + 托管 | `npm run build` + Nginx |
| 进程数 | 1（`--reload`） | 1 | **1**，见 §8.2 |

配置模板已入库：`backend/.env.example`。


## 4. 首次启动（单端口形态，推荐首跑）

```powershell
cd d:\main\park-digital-twin

# 1) 虚拟环境与依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

# 2) 演示数据（幂等，已存在可跳过）
.\.venv\Scripts\python.exe tools\gen_demo_data.py

# 3) 前端构建（含 Cesium 静态资源拷贝）
cd frontend
npm install
npm run build
cd ..

# 4) 启动
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
# 终端 1 —— 后端，工作目录 backend 或加 --app-dir backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000 --app-dir backend

# 终端 2 —— 前端
```

`vite.config.ts` 把 `/api` 代理到 `127.0.0.1:8000` 且 `ws: true`；WebSocket 路径是 `/api/ws/realtime`，因此**不需要单独配 `/ws` 代理**。后端换仓库、换端口时只改 `vite.config.ts` 一处。

## 6. 数据源切换

### 6.1 切到 PostGIS

```powershell
# 1) 起库（首次拉镜像较慢）
docker compose up -d postgis

# 2) 装驱动 + 灌数据
.\.venv\Scripts\python.exe -m pip install asyncpg
$env:DATABASE_URL = "postgresql://park:park@localhost:5432/park_twin"
.\.venv\Scripts\python.exe backend\scripts\load_postgis.py

# 3) 启动
$env:DATABASE_URL = "postgresql://park:park@localhost:5432/park_twin"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --port 8000
```

宿主机直接跑后端时用 `localhost`；**后端若在容器内，必须把 host 换成 `postgis`**（compose 服务名）。

验证切换成功：启动日志变为 `仓库: PostGIS`，页面底部状态栏「数据源」显示 `PostGIS`，前端零改动。

`backend/scripts/load_postgis.py` 的行为约定：

- 执行 `backend/sql/001_schema.sql`，全部 `CREATE … IF NOT EXISTS`，可重复执行；
- 图层按 `layer_key` **先 DELETE 再 INSERT**，楼栋明细/园区元数据是 UPSERT；
- 告警表 `dt_alarm` 会被 **`DELETE` 后重灌演示告警** —— 重复导入等于重置告警状态，生产环境不要随手重跑；
- 导入的是原始要素，**LOD 在服务层实时生成**，库里只有一份数据。

### 6.2 需要 OGC WMS/WFS 时

```powershell
docker compose --profile ogc up -d     # postgis + geoserver:8080
```

默认不启动。GeoServer 只在「第三方 GIS 客户端 / 上级平台要按 WMS/WFS 取图」时才有必要，主链路前端走 `/api` 的轻量化 GeoJSON，不依赖它。

## 8. 部署

### 8.1 发布包构成

```
发布物/
├── backend/          app/  scripts/  sql/  requirements.txt  .env
├── data/             *.geojson  *.json        # 原始要素，必须随包
└── frontend/dist/    index.html  assets/  cesium/ Assets/ Workers/ Widgets/
```

三条硬性顺序约束：

1. **先构建前端，再启动后端**。`app/main.py` 在导入时判断 `settings.frontend_dist.exists()`，不存在就永久跳过静态挂载，运行期不会再补挂。
2. **`dist/cesium/` 必须一起发**。这是 `copy-cesium.mjs` 拷进 `public/` 的 Cesium 运行时资源（Workers / Assets / Widgets / ThirdParty），缺了会出现场景白屏或 404。
3. **`data/` 必须随包**。内存仓库模式下它是唯一数据源；即使切了 PostGIS，`load_postgis.py` 也依赖它。

不要发的东西：`.venv/`、`node_modules/`、`backend/__pycache__/`、`backend/.pytest_cache/`、`backend/.env`（按环境单独注入）。

### 8.2 生产进程

```bash
# Linux
.venv/bin/python -m uvicorn app.main:app --app-dir backend \
  --host 127.0.0.1 --port 8000 --workers 1 --log-level info
```

**当前版本必须 `--workers 1`、单实例**，原因在架构里：遥测模拟器、告警状态、TTL 缓存都是**进程内对象**（挂在 `app.state` 与模块级单例上）。多 worker 会得到 N 份独立的模拟器与缓存，表现为：WebSocket 推送出现重复/跳变、在一个 worker 确认的告警在另一个 worker 仍显示未确认、缓存命中率下降。

要横向扩容，先做三件事之一：遥测外置到 MQTT/Redis、告警与缓存改共享存储、把 WebSocket 收敛到单实例。这些都是「接真实设备」阶段的活，不在演示版本内。

如需多副本但仍要单进程语义，用 `--workers 1` + 多实例 + Nginx 一致性路由，成本高于收益，不建议。

### 8.4 Nginx（形态 C，推荐生产拓扑）

Nginx 直接托管 `dist`，`/api` 含 WebSocket 反代到 Uvicorn。这样静态资源走 Nginx 的 gzip/缓存，Uvicorn 只处理接口。

```nginx
server {
    listen 80;
    server_name park.example.com;
    # 生产务必配 TLS，并将 WebSocket 的 Upgrade 头透传
    client_max_body_size 8m;

    root /opt/park-digital-twin/frontend/dist;
    index index.html;

    # Cesium 资源体积大且带版本戳，长缓存
    location /cesium/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 带 hash 的构建产物，同样长缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # WebSocket 默认 20s 心跳，留足余量
        proxy_read_timeout 300s;
        proxy_buffering off;          # 实时推送不要攒包
    }

    location = /docs      { proxy_pass http://127.0.0.1:8000; }
    location = /openapi.json { proxy_pass http://127.0.0.1:8000; }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

用这种拓扑时后端可以把 `FRONTEND_DIST` 指向一个不存在的路径（避免 Uvicorn 重复托管），前端构建也无需设 `VITE_API_BASE`（仍是同源 `/api`）。

### 8.5 Windows 服务器

无 systemd 时用 NSSM 把 Uvicorn 注册成服务：

```powershell
nssm install ParkTwin "D:\park-digital-twin\.venv\Scripts\python.exe" `
  "-m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --workers 1"
nssm set ParkTwin AppDirectory "D:\park-digital-twin"
nssm set ParkTwin AppStdout "D:\park-digital-twin\logs\api.log"
nssm set ParkTwin AppStderr "D:\park-digital-twin\logs\api.err.log"

```

前端静态资源交给 IIS 或 Nginx for Windows，规则同 §8.4（必须为 `/api` 开 WebSocket 透传）。

### 8.6 发布与回滚

```powershell
# 发布：目录级切换，不原地覆盖
# /opt/park-digital-twin/releases/<timestamp>/  +  current 软链指向

cd frontend; npm ci; npm run build; cd ..

# 回滚：软链指回上一个 release，重启服务即可
# 数据层无需回滚：LOD 不落库，schema 全部 IF NOT EXISTS
```

停机窗口来自「前端构建 + 进程重启」，通常 < 10s。静态资源带 hash，不存在 CDN 脏缓存问题。

## 9. 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开 8000 是 JSON 而不是页面 | `frontend/dist` 不存在，静态挂载被跳过 | 先 `npm run build`，顺序不能反 |
| 页面白屏 / 控制台 404 `/cesium/Workers/…` | `dist/cesium/` 未发布，或 Nginx 未托管该前缀 | 补齐 `public/cesium` 并重新构建 |
| 顶部一直「重连中」 | 反代未透传 `Upgrade`/`Connection`，或 `proxy_buffering on` | 按 §8.4 补头，关 buffering |
| 接口 200 但页面无数据 | `CORS_ORIGINS` 未含前端来源（跨域部署） | 填明确域名；同源部署无需配置 |
| 切了 `DATABASE_URL` 仍是内存仓库 | 变量未进进程，或未装 `asyncpg` | 看启动日志 `仓库:`；`pip install asyncpg`；确认变量在启动前注入 |
| `load_postgis.py` 报 `请先安装依赖: asyncpg` | 依赖在 `requirements.txt` 里是注释状态 | `pip install asyncpg` |
| 端口 8000 被占用 | 上一次进程未退出 | `Get-NetTCPConnection -LocalPort 8000` → `Stop-Process -Id <pid>` |
| 改 `.env` 不生效 | 配置在导入时读取一次 | 重启进程 |
| 告警确认后刷新又出现 | `load_postgis.py` 重灌了 `dt_alarm` | 重灌即重置，属预期 |
| WebSocket 数据重复/跳变 | 起了多个 worker | `--workers 1` |

## 10. 上线前必做（当前版本未包含）

按风险排序，都是「能跑」与「能对外」之间的差距：

| 项 | 现状 | 上线要求 |
| --- | --- | --- |
| 鉴权 | 无，`/api/devices/{id}/command` 与 `/api/alarms/{id}/ack` 完全开放 | 至少网关层鉴权 + 反控接口单独授权 |
| 传输 | HTTP/WS 明文 | Nginx 终止 TLS，WS 走 `wss` |
| 存活探针 | 无 `/health`，可拿 `GET /api` 替代 | 建议补独立 `/health`（不经过缓存） |
| 日志 | stdout，`logging.basicConfig` | 落盘 + 轮转（journald / NSSM 重定向） |
| 数据持久化 | 内存仓库，重启即回到种子数据 | 生产强制 PostGIS，`pgdata` 卷做备份 |
| 数据库迁移 | 无迁移框架，`001_schema.sql` 手工执行 | 引入 Alembic 或至少版本化 SQL 目录 |
| 遥测 | 进程内模拟器，重启重新生成 | 换 MQTT 接入，设备读数入 `dt_device_reading` |
| 限流/压缩 | 无 | Nginx 层开 gzip + `limit_req` |
| 容量 | 单进程，万级要素 | 要素 > 5 万再上矢量瓦片 / 3D Tiles |

## 附录：容器化（已入库，一条命令起全栈）

仓库根目录已有 `Dockerfile`（多阶段：Node 构建前端 → Python 运行）与 `.dockerignore`，`docker-compose.yml` 增加 `api` 服务：

```powershell
docker compose up -d --build            # api + postgis + redis + gateway，自动等库、导入、起服务
docker compose up -d --scale api=2      # 多副本（网关自动按副本轮询）
docker compose logs -f api              # 观察导入过程与访问日志
docker compose down                     # 停止（加 -v 连数据卷一起删）
```

访问 <http://127.0.0.1:8000>，底部状态栏「数据源」显示 `PostGIS`。

| 关键点 | 说明 |
| --- | --- |
| 前端构建 | 镜像内执行 `npm ci && npm run build`，`prebuild` 会把 Cesium 静态资源拷进 `dist`，无需手工拷贝 `public/cesium` |
| 数据导入 | `docker/entrypoint.sh` 先等库（最多 60s，失败则退出而非带病启动），再跑 `load_postgis.py`（幂等），最后 `exec uvicorn` |
| 退回内存仓库 | 注释掉 compose 里的 `DATABASE_URL` 与 `REDIS_URL` 即可，容器会自动跳过导入，零外部依赖 |
| 跳过导入 | `LOAD_ON_START=0`（已有数据、或只读挂载时用） |
| 多副本 | api 不对外暴露端口，统一经 `gateway`（Nginx）轮询；扩缩容后网关按 DNS 重新解析，无需重启 |
| 直连副本排障 | `docker compose exec park-digital-twin-api-1 curl -s localhost:8000/api/health` |
| 非 root | 镜像内以 `park` 用户运行；`--workers 1` 见 §8.2（多副本靠副本数扩，不靠 worker） |
| 健康探针 | 镜像与 compose 都配了 `HEALTHCHECK`（`/api/health` 带 `instance`/`bus` 字段），`docker ps` 直接看 healthy |

**多副本前提**：`REDIS_URL` 必须配置。四处进程内状态已外置——缓存（共享命中率）、事件广播（Pub/Sub）、设备状态（Hash + 选主租约）、告警确认（落 `dt_alarm.acked_at`）。不配 Redis 时行为与单进程完全一致，只是不能扩副本。

> 镜像实测 **226 MB**（含 Cesium 静态资源与演示数据）。若要进一步瘦身，可把 `/app/frontend/dist` 与 `/app/data/tileset` 外移到对象存储/CDN —— 那是 P1 的事，见 `docs/05-双引擎与云原生可行性.md`。
