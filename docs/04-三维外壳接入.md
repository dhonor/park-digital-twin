# P1：三维外壳（3D Tiles）接入

> 目标：把「倾斜摄影 / 激光点云 → 3D Tiles → 浏览器」这条链路打通，并解决它与矢量业务层共存的问题。
> 本文写的都是本仓库已经实现并验证过的内容，不是设想。

---

## 1. 成果物形态

| 项 | 约定 |
| --- | --- |
| 规范 | 3D Tiles 1.1（glb 内容）或 1.0（b3dm 内容），CesiumJS 都能直接吃 |
| 目录 | `data/tileset/`，入口固定为 `tileset.json` |
| 坐标系 | 瓦片 `transform` 负责 ENU/ECEF，**glTF 内部必须是 Y-up** |
| 挂载 | 后端把该目录挂到 `/tiles`，前端按 `/tiles/tileset.json` 加载 |

换成真实成果只要三步：

```powershell
# 1) 清掉演示替身
Remove-Item data\tileset\* -Recurse -Force
# 2) 把倾斜摄影切片产物（tileset.json + *.b3dm/*.glb + 纹理）放进 data/tileset/
# 3) 重启后端（或改 .env 的 TILESET_DIR 指向别处）
```

前端、接口、样式一行都不用改。拿不到瓦片时 `/api/tileset` 返回 `available: false`，前端自动退回矢量体块并提示。

## 2. 演示替身是怎么来的

`tools/gen_demo_tileset.py` 用现有建筑体块挤出棱柱，生成一个符合规范的壳：

- 根瓦片 `shell.glb`：整园合并，远景只加载它；
- 12 个子瓦片 `b01.glb … b12.glb`：近景按视锥细化；
- `refine: REPLACE`，根 `geometricError = 24`，叶子为 0。

产物体积约 45 KB / 330 顶点，够小，但足以验证整条链路（含瓦片细化）。

**它不是倾斜摄影**，`asset.extras.source` 标注为 `vector-extrude-standin`，接口会如实返回；不要拿它当精度参考。

## 3. 前端做了四件事

代码集中在 `frontend/src/cesium/scene.ts`：

### 3.1 加载与进度

`Tileset.fromUrl()` + `loadProgress` / `allTilesLoaded` 事件，遍历 `root.children` 统计 `contentAvailable` 得到真实百分比，喂给现有的 `map-loading` 遮罩（「正在加载三维模型 63%」）。

### 3.2 矢量层退化为「隐形拾取代理」

外壳本身不带业务属性（真实倾斜摄影更没有），所以**业务拾取仍然走矢量层**：

- 模型模式下，`polygon.material` 的 alpha 设为 0（不可见但可拾取）；
- 选中/悬停时才给 0.26 / 0.1 的罩色，读作高亮；
- 拾取代理整体抬高 **5 cm**，避免与外壳共面导致拾取深度打架；800 m 视距下 5 cm 不到一个像素。

外壳命中时还有兜底：`scene.pickPosition()` 拿到世界坐标 → 经纬度 → 点在多边形内 → 反查楼栋。这条路径对不带任何元数据的真实倾斜摄影同样有效。

### 3.3 楼层裁剪用 5 个裁剪面

`ClippingPlaneCollection` 由「4 个竖直面 + 1 个水平面」组成一个盒子，只切当前选中的那栋楼：

```
东/西/北/南 四个竖直面 → 限制在楼栋包围盒内（不外溢到邻楼）
上表面水平面            → 切到第 N 层
```

这样不需要为剖切重新切片，换成真实瓦片也一样能用。裁剪面在 ENU 下构造、转到世界坐标后赋给 tileset 的常驻 `clippingPlanes`（注意：该属性不接受 `undefined`，要清空用 `removeAll()` + `enabled = false`）。

### 3.4 模型 / 体块双模式

顶栏「建筑表现」一键切换，`?shell=vector` 可直接落到矢量模式，便于对比与排障。

## 4. 三个必须知道的坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| **glTF 是 Y-up** | 建筑横躺、整体倾斜错位 | 顶点写入前换轴：`(east, north, up) → (east, up, -north)`；3D Tiles 1.1 已废弃 `gltfUpAxis` 提示，不能指望它 |
| **`COLOR_0` 是线性空间** | 颜色整体发灰发白 | 把设计色先 `**2.2` 转线性再写入，显示时正好还原 |
| **裁剪面法线方向** | 要么全被裁掉，要么毫无效果 | Cesium 保留 `dot(normal, p) + distance >= 0` 的一侧，法线要指向**保留区**（盒子内侧） |

前两个是本仓库踩过并已修复的（见提交与 `tools/gen_demo_tileset.py` 注释），第三个按上述约定实现后一次通过。

## 5. 性能与验收

演示数据太小，看不出压力，真实项目按这套预算验收：

| 指标 | 一等界面（触屏一体机/办公本） |
| --- | --- |
| 首屏瓦片加载量 | ≤ 8 MB |
| 单帧三角面 | ≤ 250 万 |
| drawcall | ≤ 800 |
| 1080p 帧率 | ≥ 30 fps（集显） |
| 最大屏幕空间误差 | 16（`maximumScreenSpaceError`，可按机型调 8~24） |

验收时要求建模方同时交付「瓦片统计报告」（节点数、各 GE 下的加载量），否则前端无法判断是模型问题还是网络问题。

## 6. 与矢量层的关系：双轨，不二选一

| 职责 | 归属 |
| --- | --- |
| 视觉（外观、材质、真实感） | 3D Tiles |
| 业务（统计、筛选、高亮、点位、标签） | 矢量图层 |
| 拾取 | 矢量隐形代理（主）+ 世界坐标反查（兜底） |
| 剖切 | 裁剪面（作用于外壳），体块同步改 extrude 高度 |

这也是「数据轻量化优先」的延伸：**用外壳解决观感，用矢量解决业务**，两边各自做最擅长的事，避免把业务属性硬塞进瓦片。

## 7. 下一步（P2）

外壳只解决「看起来真」。要继续往下走：

1. 重点楼栋 BIM 精模（IFC → 3D Tiles），按楼层拆子节点，进入建筑时加载；
2. 室内空间与房间属性（资产编码打通）；
3. 设备低模 + 遥测绑定；
4. 管网参数化实体（`PolylineVolume`）+ 地面裁剪。

P2 的改造点：`loadBuildings` 之外新增 `loadInterior`，楼层剖切从「裁剪面」升级为「按楼层子节点显隐」。
