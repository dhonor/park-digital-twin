# 数据模型与接口

## 1. 数据分层

```
data/                     原始要素（唯一真源，轻量化在服务层生成）
├── park.json             园区元数据：中心点、边界、相机、规模指标
├── layer_boundary.geojson
├── layer_buildings.geojson      Polygon[]  + height/floors/type
├── layer_roads.geojson          LineString[] + level(main/branch)
├── layer_green.geojson          Polygon[]  + kind(lawn/plaza/water)
├── layer_trees.geojson          Point[]    + height/crown
├── layer_pipes.geojson          LineString[] + type(water/sewage/power/network)
├── devices.geojson              Point[]    + type/status/metric/building_id/floor
├── building_details.json        楼栋明细：分层面积、房间、人员、24h 能耗
└── alarms.json                  告警种子
```

约定：

- 坐标系一律 `EPSG:4326`（WGS84 经纬度）。
- 几何坐标带高程（园区基准标高 8 m），但**轻量化后只保留 x/y**——高程由渲染层的 `height / extrudedHeight` 统一控制，能省掉 1/3 坐标体积。
- 设备点的 `altitude` 由 `基准标高 + (楼层-0.5) × 层高` 推导，属性面板与 3D 场景共用同一口径。

## 2. 图层与 LOD

| 图层 | 几何 | 默认可见 | 说明 |
| --- | --- | --- | --- |
| `boundary` | Polygon | 是 | 园区红线，同时驱动场景承载面 |
| `buildings` | Polygon | 是 | 2.5D 拉伸体块，非 BIM |
| `roads` | LineString | 是 | 主干/支路分级控制线宽 |
| `green` | Polygon | 是 | 草坪 / 广场 / 水体 |
| `trees` | Point | 是 | 点位 + 树冠半径，不加载模型 |
| `pipes` | LineString | 否 | 给水/污水/电力/网络 |
| `devices` | Point | 是 | 实时值 + 状态，LOD0 只留 id/status |

LOD 属性白名单（节选，完整定义在 `backend/app/domain/catalog.py`）：

```python
LOD1_BUILDING_ATTRS = ("id", "name", "type", "type_label", "height", "floors", "color")
LOD0_BUILDING_ATTRS = ("id", "name", "height", "type")
LOD0_DEVICE_ATTRS   = ("id", "status")     # 200 台设备从 65 KB 降到 ~20 KB
```

## 3. HTTP 接口

基址 `/api`，OpenAPI 文档 `/docs`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/park` | 园区元数据 + 能力声明 |
| GET | `/layers` | 图层目录（要素数、源体积、各 LOD 属性） |
| GET | `/layers/{key}` | 轻量化图层，参数 `lod / bbox / limit` |
| GET | `/lightweight/report` | 全图层轻量化体检报告（含 gzip 实测） |
| GET | `/buildings` | 楼栋列表（含设备数、告警数、今日能耗） |
| GET | `/buildings/{id}` | 楼栋详情：分层、设备、告警、能耗曲线 |
| GET | `/devices` | 设备点位，参数 `lod / type / status / building_id / bbox` |
| GET | `/devices/{id}` | 单设备（含实时值） |
| POST | `/devices/{id}/command` | 反控演示通道 `{action:"restart"}` 或 `{action:"set",value:50}` |
| GET | `/overview` | 综合态势 KPI + 设备状态分布 + 24h 用能 |
| GET | `/energy/summary` | 园区与分楼能耗曲线、Top5、能耗强度 |
| GET | `/alarms` | 告警列表，参数 `level / status` |
| POST | `/alarms/{id}/ack` | 确认告警 |
| GET | `/health` | 健康检查 |
| WS | `/ws/realtime` | 实时推送 |

## 4. 实时协议（WebSocket）

连接：`ws://{host}/api/ws/realtime`

```jsonc
// 1) 连接即下发
{
  "type": "hello",
  "ts": "2026-11-10T11:00:00+08:00",
  "park": { "id": "park-yczg", "name": "云创智谷", "center": [120.0794, 30.2818] },
  "lods": [{ "lod": 0, "key": "LOD0", "label": "概览" }],
  "interval": 2.0,
  "devices": [{ "id": "DEV-B01-001", "status": "normal", "metric": { "value": 42.1 } }],
  "alarm_counts": { "critical": 4, "warning": 3, "info": 0 },
  // 连接即带一份 KPI，前端首屏不必再单独请求 /api/overview
  "overview": { "kpi": ["..."], "device_status": { "normal": 156 }, "updated_at": "..." }
}

// 2) 周期遥测（只推变化的设备）
{ "type": "telemetry", "ts": "...", "items": [{ "id": "DEV-B01-001", "status": "warning", "value": 63.2, "metric": "power", "unit": "kW" }] }

// 3) 规则触发的告警
{ "type": "alarm", "alarm": { "id": "ALM-RT-0007", "level": "critical", "title": "...", "device_id": "...", "value": 71.2, "unit": "kW" } }

// 4) KPI 周期推送（5s，结构同 GET /api/overview）
{ "type": "overview", "ts": "...", "overview": { "kpi": ["..."], "device_status": { "normal": 156 }, "energy": { "today_kwh": 1753040.0 }, "updated_at": "..." } }

// 5) 20s 无消息时的心跳
{ "type": "ping", "ts": "..." }
```

前端处理：`telemetry` 只更新点位颜色与面板数值，不重建场景；`alarm` 追加到告警流；`overview` 直接替换 KPI，**WS 在线时不再轮询 `/api/overview`**（仅断线时回退到 5s 轮询）。断线自动重连（指数退避，上限 8s）。

> KPI 由服务端 `OverviewService` 统一组装：静态部分（能耗、碳排、在园人数、24h 曲线）启动时算一次并缓存，动态部分按遥测快照重算；**没有订阅者时直接跳过**，不空转。多终端场景下 `overview` 从「每终端 12 次/分钟」变成「服务端 12 次/分钟，终端数无关」。
>
> 多副本时（配置 `REDIS_URL`），上述事件由**持有选主租约的副本**产生并发布到 Redis Pub/Sub，其余副本订阅后转给本进程的 WS 连接 —— 所以连到哪个副本都看到同一份流。未配置 `REDIS_URL` 时退化为进程内扇出，协议完全不变。

## 5. PostGIS 表结构

见 `backend/sql/001_schema.sql`。核心表：

| 表 | 用途 | 备注 |
| --- | --- | --- |
| `dt_park` | 园区元数据 | `detail jsonb`，与 API 响应同构 |
| `dt_layer_feature` | 统一要素表 | `(layer_key, feat_id)` 主键，`geom geometry(Geometry,4326)` + GIST 索引 |
| `dt_building_detail` | 楼栋明细 | 与几何解耦，点开才查 |
| `dt_alarm` | 告警 | `ts` 降序索引 |
| `dt_device` / `dt_device_reading` | 真实 IoT 接入预留 | 读数建议按月分区或 TimescaleDB |

导入：

```bash
set DATABASE_URL=postgresql://park:park@localhost:5432/park_twin
python backend/scripts/load_postgis.py
```

导入的是**原始要素**，LOD 依旧由服务层实时生成。
